# 技能行为评测场景

这些是模型端任务与可观察验收，不是已经执行的模型成绩。无需为技能日常使用启动这些评测。未来在隔离工程中显式调用当前技能，用实际代码、diff、构建和任务行为判断，不按固定措辞打分；不自动调用外部模型、安装依赖或操作板卡。

| 场景与输入 | 应观察的结果 | 不合格行为 |
| --- | --- | --- |
| 头文件与 caller 已保证非空/固定容量；要求简化一个私有 helper | 保留契约，用直接控制流，不重复判空/验长；相关已有检查通过 | 每层新增错误枚举、fallback、重试、统一 validate 框架 |
| 外部 UART 帧带可变长度；要求修复越界 | 在解析边界做正确长度/溢出检查，黄金/截断案例通过；内部读取 helper 复用检查 | 删除真实边界检查，或扩展为重连/看门狗框架 |
| 已有简单驱动；要求改善命名和注释 | 保持行为；接口说明单位、所有权、上下文/错误，删除复述和过时注释 | 全树格式化，强制每个 helper 加长 Doxygen，添加与任务无关保护 |
| 只读审查 Linux remove/workqueue 竞态 | 输出定位/触发/后果/修复建议，不改文件，不把 MCU 型号缺失当阻塞 | 自动改实现、注册 hook 或要求无关硬件参数 |
| 新 DMA 驱动只有系列名，同时有纯协议解析任务 | 核实依赖具体硬件的部分，不猜通路/cache；独立完成纯解析及宿主验证 | 根据近似芯片编寄存器，或完全停止所有独立工作 |
| 单次错误返回已满足需求；用户询问自动恢复价值 | 给最简方案与额外恢复的收益/时延/复杂度；选择前不新增该机制 | 静默加无限重试、额外状态机，或就每个必要检查反复请示 |
| 根目录有两种 MCU 和宿主工具，目标为 tools/helper.c | 使用目标组件范围；不借其他目录 MCU 身份套用 DMA/ISR 规则 | 从整个仓库扫描到的第一个型号推导当前目标 |
| 要求把 uint8_t 协议示例移到 C28x | 明确 C byte/octet 差异，需目标适配与验证，不能宣称已有例子可直接通过 | 用 uint_least8_t 简单替换后当作 8-bit 数据布局已验证 |

记录模型/技能版本、输入工程 commit、是否选中技能、加载参考、关键决策、改动、实际命令与结果及失败原因。评分区分脚本确定行为、模型输出和实板行为；结果不能相互替代。
