# 适度设计：简单、可读、必要的正确性

这是本技能的默认实施取舍，适用于所有 profile。领域规则只在本次改变涉及该风险时应用；不能为了“符合可靠性技能”补齐与任务无关的框架、配置或检查。

## 默认直接实现

`SIM-01` 必须：优先现有模块/SDK API、清晰控制流和明确数据结构。只为实际变化或复用提取接口；单一实现不默认增加策略/工厂/插件/虚拟总线。函数拆分依据职责、状态或硬件边界，不按任意行数把直线逻辑拆碎。

`SIM-02` 必须：输入验证放在实际边界。外部报文、用户空间数据、跨模块可变长度/所有权等风险处保留必要长度、范围、错误和寿命检查；内部静态 helper 若前置条件已由调用者保证，不重复判空/验长/CRC。用接口注释、类型、编译期断言、项目既有 assert 或测试表达这些保证，按场景选择，不全部堆上。

`SIM-03` 必须：硬件手册要求、真实越界/溢出、错误返回、异步寿命、并发正确性与必要资源释放属于实现本身；用最小修复满足它们。不能靠返回成功、吞错或取消必需的验证来减少行数，也不因一个 review 线索重写整个模块。

`SIM-04` 建议：正常路径直观，错误路径短而完整。使用工程已有错误风格；多资源清理可用清楚的 `goto cleanup`。无真实异步状态就不用状态机；无共享可变数据就不加锁；已存在生命周期约定就不加引用计数；不为任意可能性设计多层 fallback。

## 额外保护由用户取舍

`SIM-05` 必须：下列机制在**没有现成项目要求或已授权设计依据**时，先提出具体选择，用户决定后再做依赖它的步骤。简单正确的主体实现和独立验证继续进行。不要对每个参数检查重复询问。

| 可选机制 | 提案必须说明 |
| --- | --- |
| 自动重试、重连、复位、后台健康监测 | 真实故障场景、幂等性/副作用、次数/时限、额外状态与测试成本 |
| 冗余存储、双副本、软件看门狗、复杂恢复状态机 | 可靠性目标、现有硬件/系统是否已覆盖、RAM/Flash/运行代价 |
| 引用计数/通用对象池/万能 HAL/锁自由队列 | 当前具体需要、比简单所有权/现有接口更合适的证据 |
| 新静态分析依赖、全仓扫描、大规模重构 | 可捕获什么、现有工具为何不足、改动与维护范围 |

建议表达：`当前单次返回错误已满足任务。可选增加最多 N 次重试，但会增加时延和状态，且需确认该命令幂等。建议先保留直接返回；若需要自动恢复，可选增加重试。` N 必须从需求/事实获得，未知时不要随意填默认值。

项目已有要求的保护直接遵守，不重新请求同范围批准；发现已确认的正确性缺陷直接做已授权范围的最小修复。真正需要额外用户决定时只暂停依赖项，不把整项任务变成审批清单。

## 注释和可维护性

`SIM-06` 必须：变量/函数名先表达目的；注释解释无法由名称直接表达的约束和原因。公开接口有简短契约，内部明显 helper 可无注释。修改行为时同步更新对应注释，过时注释应修正或删除。具体示例见 [代码书写](code-style.md)。

## 工作量与能力边界

- 简单命名/注释/局部等价重构：复用已知上下文，不要求完整 MCU 问卷、资源预算表、所有专题或新增测试；跑项目要求及相关轻量检查。
- 行为改变：只确认受影响的输入、所有权、上下文、错误与验证；不为了模板填无关字段。
- 新驱动、迁移、DMA/并发/存储改变：加载相关系列与专题，必要事实不足时暂停该硬件相关部分，继续纯逻辑部分。
- 先用既有构建/分析工具；检测器只给线索，不能证明没有 UAF/竞态。没有工具/板卡时说明未验证，不自动安装依赖、刷板或调用收费模型。
- 同一批编辑读取一次底线及相关参考；只在目标、运行上下文或约束变化时重读。修改文件检测一次，确认的失败才追加修复和验证；不不断扩大审阅范围。
