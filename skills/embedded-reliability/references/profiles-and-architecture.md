# 平台划分与架构

## Profile 决策

| Profile | 语言/类型 | 资源与同步 | 外设访问 | 验证方式 |
| --- | --- | --- | --- | --- |
| linux-kernel | 目标内核支持的 GNU C；`u32` 等内核类型 | 内核分配、refcount、mutex/spinlock 等 | 子系统 API、regmap、MMIO/DMA API | Kbuild、sparse、KUnit、kselftest、目标内核 |
| linux-user | 项目 C/C++ 方言；POSIX、libc | 堆/池、fd、pthread、RAII | IIO、SocketCAN、gpio character API、已有服务 | 原生与交叉构建、sanitizer、集成、目标板 |
| mcu-rtos | 编译器/SDK 明确支持的方言 | 静态/池/受控堆、RTOS/ISR 原语 | 厂商 HAL/LL、BSP、硬件 DMA/缓存 API | 宿主纯逻辑测试、交叉链接、实板/HIL |
| portable-core | 所有目标共同支持的 C/C++ 子集 | 显式调用者存储或明确所有权 | 不直接访问 OS、寄存器或厂商头文件 | 跨工具链、数据模型和字节序测试 |

同一产品可以使用多个 profile；“项目使用 C11”不能推导内核或所有 MCU 组件也遵守 ISO C11 模式。Linux 内部 API 不保证跨版本稳定，核对目标源码树而非只看 latest 文档。[Linux 驱动接口说明](https://docs.kernel.org/process/stable-api-nonsense.html)

## 依赖设计

`ARC-01` 必须：业务策略和纯算法通过窄接口使用平台能力，不让平台回调反向包含业务私有实现。依赖图按编译期 include/link 与运行期调用分别检查，回调不等于编译期循环依赖。

建议的多平台组织（按已有仓库调整，不能为套目录重构）：

```text
app/                    产品流程、策略、状态机
services/               采集、通信、存储等稳定能力
core/                   可宿主测试的算法、协议、模型
ports/linux/            POSIX、设备节点、系统服务适配
ports/rtos/             RTOS 与 SDK 适配
drivers/linux/          Kbuild 内核驱动，不能链接用户态 core
bsp/                    引脚、时钟、电源、板级配置
interfaces/             版本化协议/UAPI 定义，不共享内部对象布局
tests/                  纯逻辑、集成与 HIL
```

典型运行链：Linux 应用 → 采集服务 → IIO 用户接口 → IIO 芯片驱动 → SPI/I²C 控制器 → 外设。MCU 链：应用 → 服务/状态机 → 设备驱动 → 总线/HAL → BSP。Linux 内核已有该分层时直接使用，不另造万能 HAL。适配层只隔离实际差异。

`ARC-02` 必须：至少分开策略、外设机制和线格式。协议解析不发送电机指令，ADC 驱动不决定产品告警阈值；确认消息有效后由策略执行动作。

`ARC-03` 建议：同一模块拥有状态和资源，用显式上下文支持多实例；跨模块全局变量不是默认通信方式。状态机只有真实异步阶段时引入，不为同步小函数新增框架。

`ARC-04` 必须：跨 Linux↔MCU、进程↔内核边界明确版本、字段宽度/字节序、最大帧、单位、时间基准、能力协商、复位代次、序号回绕、重连和错误码。不能共享裸指针、`long`、原生 enum 或 `sizeof(struct)` 作为线协议。

`ARC-05` 必须：错误分为非法输入、暂时不可用、超时、设备故障、数据损坏、资源耗尽、取消；每类确定重试是否安全、次数与总时限、降级/上报/复位条件。初始化失败不能留下“看似 ready”的实例。

`ARC-06` 必须：以预算约束设计，数值从需求/测量获得：最坏输入速率、吞吐、队列容量、单次处理上限、线程栈、堆峰值、CPU 占用、截止期和恢复时间。无需求不能宣称硬实时；平均时延不能替代最坏情形。

## 接口收敛

在相邻头文件或契约写明：谁初始化、启动、停止、释放；允许的状态转换与重复调用语义；同步返回还是异步完成；回调上下文/重入/持锁行为；输入借用或转移；输出分配者；取消返回后是否还可能回调；数据单位与短读；耗尽/拔出时的表现。不能用成功码掩盖丢样。

同一编解码模块在 32/64 位、大小端、不同 `char` 符号性下保持线格式一致；不具备的构建目标标未验证。共享源码不要求共享运行时对象。共享内存还需同步、对象寿命及进程崩溃恢复。

配置项：RTOS 种类、kernel commit/config、libc、C++ 运行库、PREEMPT_RT、ABI 兼容窗口、第三方库。不能凭平台名补全。
