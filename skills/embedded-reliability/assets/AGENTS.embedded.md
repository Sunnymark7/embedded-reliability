# 嵌入式开发补充规则

此为可合并片段。仅在用户要求建立项目规范时加入适用的 AGENTS.md，保留已有要求；不要把本文件复制成覆盖整个项目的替代品。

- 每次任务先从源码/构建识别 linux-kernel、linux-user、mcu-rtos、portable-core 及 C++ 组件，采用各自工具链、类型与同步机制。
- 需要时使用 `$embedded-reliability`，按当前领域加载参考；普通小改不全量运行架构流程。
- 固件/驱动实现、审阅或移植时应用该技能；从 context 线索核对完整 MCU part/revision/SDK，再加载命中系列。编辑前读可靠性底线；未确认 hook 生效时对改动文件手动 detect。
- 先明确本次接口的输入/输出范围、单位、所有权、上下文、超时、错误和取消语义。
- 寄存器、清中断、DMA/缓存、SDK/API 必须有目标版本依据；未知项标出，不能猜型号/位值。
- 所有分配、指针运算、缓冲访问和外部长度先验证范围；异步资源在最后引用结束后释放。
- `volatile` 不作为线程同步；DMA 所有权/缓存维护与 CPU 锁/原子操作分别处理。
- 外部格式显式编解码；不直接发送结构体，不靠 packed/位域/union 重解释保证可移植性。
- 驱动初始化失败、停止、解绑、重连和 PM 路径与正常路径一起设计。
- 复用现有架构/依赖和风格，只改本次必要范围；审阅任务保持只读。
- 完成时报告实际构建/分析/测试证据、未执行的检查、板级验证缺口和适用偏离；不以宿主测试冒充实板通过。

具体板型、内核版本、工具链、实时/资源预算及协议参数从项目证据确定；此片段不预设数值。
